Gateway / Lighthouse Boundary

Lighthouse is the intelligence engine. The external Start9 Agent Gateway is a thin control, approval, policy, and audit plane. This page summarizes who owns what. Canonical source: docs/GATEWAY_LIGHTHOUSE_PROFILE_BOUNDARY.md (decision: ADR-0001).

Don't confuse the two "gateways." The in-repo Local Gateway (modules/local_gateway.py) is a bounded, read-only, loopback dispatch layer — a different thing from the external Gateway control plane described here.

Who owns what

Lighthouse owns (the engine)Gateway owns (the control plane)
Profile definitions, validation, (future) resolution + activation stateOperator review / approval surfaces
Intake validation, normalization, observation creationProfile-switch authorization + audit trail
Graph, temporal / tempo derivation, correlationSource-pack admission approval
(Future) candidate findings + disclosure-package preparation(Future) DMS release policy
Backup-readiness evidence about its own state—
Invariant. The Gateway never executes Lighthouse work and never writes Lighthouse data. A Gateway approval record is not authoritative approval state inside Lighthouse.

The live bridge is blocked

A future read-only, evidence-stripped bridge would let the Gateway read profile state, backup readiness, and recent findings from Lighthouse. It is blocked until a separate approved packet exposes a private REST / /local/* surface from the Start9 package — today only MCP-SSE on port 8001 is published. Until then the split stays fixture-backed on the Gateway side. See ADR-0010.
