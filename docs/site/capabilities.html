What Lighthouse Is

Lighthouse (git repository pattern-match-sentinel) is a persistent, private, local-first intelligence platform. It watches public information — SEC filings, military aviation transponder feeds, research publications, government newsrooms — normalizes each observation into a scored alert, finds moments where several independent signals point at the same organization at the same time, and records those moments as structured, queryable intelligence.

  • Local-first — designed to run on a Start9 home server; your intelligence never has to leave your machine.
  • Deterministic — the core pipeline is ordinary code, not a language model. Same inputs, same outputs, every finding explainable (ADR-0009).
  • Graph-native — every correlation becomes nodes and edges, so intelligence compounds over time.
  • Start9-integrated — packaged for a private, self-hosted home server with persistent storage and backups.

The Deterministic Pipeline

Observation → Normalization → Store → Correlation → Graph → Temporal → Findings → Operator Review → Gateway → Approved Action

The first seven stages run today and are deterministic. The last two are governed: publishing is gated and safe-by-default, and the Gateway boundary is defined but the live bridge is blocked (ADR-0010).

Core Capabilities

Observation Collection Live

Watches SEC, ADSB/OpenSky, arXiv, and government newsrooms. Each collector is fault-isolated so one failure never stops the others. Modules: *_sentinel.py, flight_tracker.py.

Observation Normalization Live

Every observation becomes one canonical, scored, provenance-stamped AlertRecord. Modules: alerts.py, scoring.py, db.py.

Weighted Correlation Live

Combines independent signals on the same entity/time window, scored 1–10. The publishable unit. Modules: correlator.py, correlation_scoring.py.

Witness Attestation Live

Each stored correlation carries a SHA-256 witness hash; signed attestations are not yet produced in the production path (the BIP-340 helper is demonstration/test-only). Module: witness.py.

Graph Intelligence Live

Correlations become queryable nodes and edges; idempotent historical backfill. Modules: graph*.py. See Graph Intelligence.

Callsign Intelligence Live

Normalizes and classifies callsigns, persists sighting history, and makes callsigns graph entities. Module: callsigns.py.

Temporal & Tempo Live

Recurrence, activity windows, operational tempo, mission recurrence — informational today. Modules: temporal_analysis.py, tempo_analysis.py.

Local MCP Interface Live

Bounded, read-only queries for tools and AI agents; a private loopback dispatch layer. Modules: portal/mcp_server.py, local_gateway.py.

Backup Readiness, Verified Backup & Restore Drill Live

Fail-closed check that authoritative state sits inside the /data boundary (READY ≠ backup performed), plus a versioned backup manifest, verified backup copy, independent verification, and an isolated restore drill: backup-readiness · backup-manifest · backup-create · backup-verify · restore-drill. SHA-256 + safe SQLite online-backup snapshots; writes only to explicit destinations; a restore drill never targets /data. Modules: backup_readiness.py, backup_manifest.py, backup_create.py, backup_verify.py. A completed backup or drill never authorizes a profile switch, and a drill is not a production restore (planned/separate).

Profile Transition Preview Live

A deterministic, read-only review artifact (profile_transition_preview.v1; profile-transition-preview): given a proposed profile transition and verified backup evidence, it describes the declarative policy diff, references the LHP-PROFILE-02 evidence (status only), and names the approvals a future Gateway must collect. Fail-closed — ready_for_review only with two valid profiles and present, passing evidence; else incomplete/blocked/invalid. Module: profile_transition.py. It activates nothing, switches nothing, and approves nothing — approval authority remains a future Gateway capability.

Intelligence Profiles Declarative + RCD v2 activation

Declarative mission bundles (data, not plugins); five bundled profile seeds, none production-ready. Narrow initial activation is shipped for repository_capability_discovery v2 only (lighthouse profile-activate). Switching, deactivation, and every other profile remain unimplemented. See Profiles.

Repository Source Packs Architecture-only

Public repos as reference-only observations — never a second engine, never executed. See Source Packs.

Gateway Integration Blocked

External control plane (approval/policy/audit). Boundary defined; live bridge blocked. See Gateway Boundary.

What Lighthouse Does NOT Do

Intentional non-features No autonomous execution · no autonomous publishing (Nostr requires NOSTR_PUBLISH_CORRELATIONS=true, not dry-run, score ≥ 7.0, ≥ 2 signals) · no cloud dependency · no hidden AI in the core · no automatic profile switching · no automatic invention publication · no autonomous Dead-Man's Switch · no silent approval bypass · no opaque scoring · no side effects in dry-run · no execution of external repositories · no hypothesis layer and no finding layer — a pattern candidate is a review object, carries no score or rank, and authorizes nothing.
The observation layer cannot say anything matters Local observation records facts about your repositories and documents and stops there. It has no score, no rank, no priority, no importance — and no word for one: a normalized fact's attribute key must belong to a closed observation vocabulary, and no column in the three fact tables can hold an opinion. Cross-scope fact discovery performs exact lookup and direct set intersection over stored facts. It does not rank, infer, score, or interpret relationships. The layer that would answer why does this matter does not exist, and will not arrive by accident.

Roadmap Context

Lighthouse reasons in phases A–K, not packet numbers. Phases A–C are complete (Foundation, Graph, Temporal); the current phase is D (Repository Intelligence — local intake shipped; external source packs remain architecture-only). Narrow RCD v2 initial activation is shipped; switching is not. See the Roadmap and canonical ROADMAP.md.

Lighthouse In One Page

Lighthouse watches public data and finds the moments where several independent signals converge on the same organization at the same time. In the legacy OSINT pipeline those moments become correlations: scored, integrity-hashed, graph-linked findings a human reviews. Its core is deterministic, it is graph-native and temporally aware, and it runs local-first on a self-hosted Start9 server. It is deliberately restrained — no autonomous action, no raw-alert publishing, no hidden AI in the core. Today, SEC + aviation correlation, graph and callsign intelligence, temporal analysis, a read-only MCP interface, a private local gateway, the observation intake layer, pattern candidates, and narrow RCD v2 initial activation (lighthouse profile-activate) are operational, backed by 2455 unit tests. Switching, SciPres activation, and StartOS exposure of this V1 loop are not shipped.

The observation layer is deliberately unable to score: it can tell you what exists, where else a fact occurs, and how confident it is that it determined the fact — but never whether the fact matters. That boundary is now explicit and accepted (ADR-0020): facts first, interpretation second, findings only after evidence and review. A repeated fact is not automatically significant, a candidate is not a finding, and a finding is not permission to publish or execute. Detector rules are profile-owned. Profile switching remains frozen (ADR-0018, ADR-0024).
