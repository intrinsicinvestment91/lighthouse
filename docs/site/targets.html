Target Profiles

How Lighthouse decides what to watch — target profiles and signal routing.

What Target Profiles Are

A target profile tells Lighthouse: "watch these entities, looking for these kinds of signals, in these regions." Profiles are stored in JSON and can be customized per deployment without changing any code.

Each profile specifies:

  • name — a unique identifier for the profile
  • entities — organization names to watch (Lockheed Martin, MIT Lincoln Laboratory, etc.)
  • keywords — terms that indicate relevance (hypersonic, fusion, directed energy, etc.)
  • signals — which collectors to activate (sec, adsb, flight, arxiv, patent, archive, narrative)
  • regions — geographic scope (e.g. nc for North Carolina, ca for California)
  • priority — high, medium, or low
  • enabled — whether the profile is active

Where They Live

FilePurpose
data/targets.jsonRuntime copy — loaded by Lighthouse on each run. Operator-customizable after deployment.
seed/targets.jsonDefault profiles seeded from the Docker image on first Start9 run. Not overwritten on updates.

Edit data/targets.json to customize your watch plan without changing the image defaults. On Start9, this file lives in the persistent /data/ volume.

Current Active Profiles

fusion_research

Tracks public and private fusion energy research organizations. Watches for SEC filings, patent activity, arXiv research publications, and archive/narrative signals related to fusion plasma, inertial confinement, and energy technology.

aerospace_defense

Tracks major aerospace and defense contractors. Watches SEC filings, ADSB/flight activity near facilities, and archive signals. Entity list includes Lockheed Martin, Boeing, Raytheon, General Atomics, and similar.

advanced_research_institutions

Tracks research universities and national laboratories involved in advanced technology programs. Covers entities like MIT Lincoln Laboratory, Stanford, Caltech. Primarily watches arXiv silence, archive/narrative signals, and patent velocity.

government_defense_labs

The strongest live signal profile. Tracks DARPA, AFRL, NRL, NNSA, and related government defense research programs. Watches ADSB, flight, archive, and narrative signals. This profile drives most of the military aviation observations in production runs.

Why DARPA is in targets but not entities.json Government agencies that do not file SEC reports use a different entity schema. DARPA appears in the government_defense_labs target profile but is intentionally excluded from entities.json (which is used for SEC CIK resolution) until a government/non-SEC entity schema exists.

How Targeted Mode Works

Running lighthouse --module targeted reads data/targets.json, builds a route plan via modules/signal_router.py, and passes scoped parameters into each collector:

  • SEC sentinel receives only the entities from active SEC-enabled profiles
  • ADSB/flight collectors receive the facility list scoped to active regions
  • arXiv sentinel receives only the researcher queries relevant to active keywords/entities
  • Archive and narrative collectors receive only the keyword-filtered targets

This reduces noise compared to running all modules with broad defaults.

Inspecting Your Route Plan

lighthouse targets
lighthouse targets --show-routes
lighthouse targets --json

--show-routes shows the resolved routing plan: which signal type is active, which entities/keywords/regions are in scope, and which profiles contribute to each route. This is read-only and has no side effects.

Facility Aliases

Facilities in the flight/ADSB configuration often have multiple real-world names. Targeted-mode facility matching uses an aliases list on each facility definition in config.py, so a target referencing "LLNL" will also match aircraft observed near "Lawrence Livermore National Laboratory" or "NIF."

Implemented aliases include:

  • LLNL ↔ Lawrence Livermore ↔ NIF (National Ignition Facility)
  • Helion Energy ↔ Everett (Helion's facility)
  • DARPA HQ ↔ DARPA (Arlington, VA)
  • Research Triangle Park ↔ RTP (NC)
  • Camp Lejeune ↔ government defense lab variants

Profile Schema

{
  "schema_version": 1,
  "targets": [
    {
      "name": "example_target",
      "entities": ["Acme Corp"],
      "keywords": ["hypersonic", "propulsion"],
      "signals": ["sec", "patent", "adsb"],
      "regions": ["nc"],
      "priority": "high",
      "enabled": true
    }
  ]
}

Allowed signals: sec, patent, arxiv, flight, adsb, narrative, archive.

Allowed priorities: high, medium, low.

Each target must include at least one entity, keyword, or region.

Edit with care Changes to data/targets.json affect which signals run and what gets correlated. Treat edits with the same care as changes to the entity seed. Validate with lighthouse targets before running the pipeline.
