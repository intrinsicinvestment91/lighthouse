Operator Guide

Running Lighthouse in production: pre-run checks, standard runs, backups, and rollback. Canonical source: docs/OPERATIONS.md. For day-to-day querying see Day-to-Day Usage; for the appliance see Start9 Deployment.

Pre-run checklist

python scripts/validate_entities.py data/entities.json
env -u NOSTR_PRIVATE_KEY_HEX -u NOSTR_PUBLISH_CORRELATIONS pytest tests/unit -v --tb=short
lighthouse --module all --dry-run --since-days 7

--dry-run performs no DB writes, no IPFS pinning, and no Nostr publishing.

Standard production run

scripts/run_lighthouse_prod.sh
# or manually:
mkdir -p backups logs
cp data/state.db backups/state-before-run-$(date +%Y%m%d-%H%M%S).db
lighthouse --module all --since-days 7 > logs/live-$(date +%Y%m%d-%H%M%S).log 2>&1

Public source checks

Check admitted public HTTPS locators and keep an append-only history of the outcomes. The trust boundary is LIGHTHOUSE_PUBLIC_SOURCE_HOSTS (comma-separated exact hostnames); empty is the default and refuses. data/public_source_targets.json is the work list and may only narrow the hosts.

export LIGHTHOUSE_PUBLIC_SOURCE_HOSTS=archive.example.org,data.example.edu   # empty => refuses
lighthouse public-sources check --targets-file data/public_source_targets.json --dry-run   # writes nothing
lighthouse public-sources check --targets-file data/public_source_targets.json             # persist (append-only)
lighthouse public-sources runs

The ledger stores the exact-byte digest and metadata, never the response body. A not_found is HTTP 404/410, not a claim that a source is gone; no candidate, no scheduler, no Gateway (ADR-0022).

Backup & rollback

The Start9 volume resets on uninstall. Take a StartOS backup before any package update to preserve historical intelligence (state.db, callsign history, graph). Backup readiness only asserts eligibility, never that a backup was performed.
  • Inspect readiness (read-only): lighthouse backup-readiness — must be READY before any future profile switch (ADR-0004).
  • Rollback DB state: cp backups/<file>.db data/state.db.
  • Authoritative state must resolve under the /data boundary; a DB_PATH outside it fails closed. See Security.

Safe publishing

Only correlation events publish, and only when all four hold: NOSTR_PUBLISH_CORRELATIONS=true, not dry-run, score ≥ 7.0, and ≥2 unique signals. Only entity, event_type, score, signals, summary may appear in a note — never raw payloads or evidence. Full detail: Security.

Graph backfill (Start9, one-time)

lighthouse graph-backfill --dry-run --limit 100   # review first
lighthouse graph-backfill --limit 100             # then apply (idempotent)

Caution: historical false-positive correlations also become graph-visible.
