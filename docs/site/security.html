Security Posture

How Lighthouse stays safe: fail-closed controls, a private surface, gated publishing, and honestly-recorded blocking items. Canonical source: docs/SECURITY.md (LHP-SECURITY-01), with the detailed register in PROFILE_SECURITY_RISKS.md.

LHP-SECURITY-01 is a consolidated posture, not a claim of full hardening. Several items below are blocking for future work and are recorded as such.

Design tenets

  • Fail closed. Missing or unverifiable safety configuration must deny, never allow.
  • Deterministic core. No LLM in correlation/scoring/witness/explanation — output is reproducible and attestable.
  • Least exposure. MCP stays private; /local/* is loopback-only; only high-signal, evidence-stripped correlations may publish.
  • Preserve intelligence. Authoritative state stays inside the /data backup boundary.

Recorded risks (register)

Dead-Man's Switch (highest). The DMS path could broadcast ciphertext with no score/approval/witness gate. Production use is blocked pending a threat model and release state machine. Profiles may declare DMS eligibility only. See ADR-0006.
Approval gate — Lighthouse side fixed. The Lighthouse MCP LIGHTHOUSE_APPROVAL_SECRET gate is now fail-closed: it denies when the secret is missing, empty or whitespace-only, when the token is absent or invalid, when the configuration is unreadable, and on any exception. Uncertainty denies. The Gateway-side approval check is a cross-repository dependency and is not re-verified here. Lighthouse retains its independent local gate as defense-in-depth regardless. See ADR-0007.
A finding is not permission. Lighthouse answers "what intelligence can be extracted from the admitted evidence?"; the Gateway answers "may a consequential action or external release occur?". Reaching the top of the evidence chain authorizes nothing, and no score at any layer may promote a candidate, authorize publication, authorize execution, override missing evidence, or suppress counterevidence. See ADR-0020.
DB_PATH backup escape. An authoritative path outside /data escapes StartOS backup. inspect_backup_readiness() fails closed on escape. See ADR-0004.

Cross-repository dependency

Lighthouse's posture depends on the separate Gateway application for approval/policy/audit. The Gateway's fail-open defect is a cross-application blocker for any live profile switch or source-pack bridge; the live bridge itself is blocked until package-side exposure is approved (ADR-0010). See the Gateway Boundary page and the Architecture Decisions.
